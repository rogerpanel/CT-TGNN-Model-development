# CT-TGNN: Continuous-Time Temporal Graph Neural Networks

Implementation and experiment pipeline for continuous-time temporal graph
learning on encrypted network traffic.

**Status: experiments in progress.** This repository contains the model,
the data pipeline, the baselines, and the evaluation harness. Results are
generated by running it. No performance figures are published here that
have not been produced by the code in this repository.

---

## Design principle: results cannot be typed in

Every metric, table, and figure is recomputed at generation time from
per-sample model outputs stored in `runs/<model>_seed<k>/scores_test.npz`.

Concretely:

- `src/train.py` writes `y_true` and `y_score` for the test split. Nothing
  else is treated as a result.
- `src/report.py` reads those arrays and derives every reported number.
  There is no code path that emits a metric from any other source.
- The ROC curve and its AUC are computed from the same array inside the
  same function call, so a curve cannot disagree with its own legend.
- `paper/provenance.txt` lists which score file produced which number.
- If a run is missing, its cell reads `n/a`. It is never estimated.

`src/data/loader.py` has no synthetic fallback. If the data cannot be
read, it raises.

## Methodology

**Chronological splits.** All training data precedes all validation data,
which precedes all test data. Random shuffling of temporally ordered
security data is data snooping and inflates results (Arp et al., USENIX
Security 2022, pitfall P3; Pendlebury et al., TESSERACT, constraint C1).

**Identifier exclusion.** Endpoint identity columns are excluded from the
feature matrix. Leaving raw IPs in lets a model memorise which host is the
attacker instead of learning attack behaviour (Arp et al., pitfall P4).

**Graph construction** (`src/data/graph.py`) implements a single-pass
`O(K log K)` algorithm:

- The adjacency carries *connection state*; the point process carries
  *usage*. If service A invokes B 1,000 times in a minute, that is **one
  edge and 1,000 interaction events** — not 1,000 edges. Keeping these
  separate preserves the piecewise-constant topology the hybrid ODE
  formulation requires.
- Edge lifetime uses an idle timeout on last activity plus a maximum
  active lifetime, mirroring NetFlow/IPFIX expiry. A long-lived
  connection with continuing requests is refreshed, not re-created, so it
  produces no spurious topology jumps.

**Node labels** are lifted from flow labels over a short window with **no
k-hop propagation**. Propagating labels to a malicious node's multi-hop
neighbourhood inflates precision and recall, a practice criticised in the
provenance-IDS literature (KAIROS, IEEE S&P 2024).

**EdgeBank** is included as a mandatory sanity check. It is pure
memorisation with no parameters. A learned model that does not clearly
beat it is not learning anything useful, and `src/report.py` prints a
warning when that happens.

## Quick start

```bash
pip install -r requirements.txt

# 1. Inspect the real dataset schema first
python -m src.data.inspect --path /path/to/dataset

# 2. Set data.path in configs/default.yaml (override columns if needed)

# 3. Smoke run
python -m src.train --model ct_tgnn --seed 0 --max-rows 50000 --epochs 2

# 4. Full sweep: 6 models x 5 seeds
bash scripts/run_all.sh

# 5. Generate tables and figures
python -m src.report --runs runs --out paper
```

On Kaggle, use `notebooks/kaggle_run.ipynb` — the dataset is already
mounted and GPU is free.

## Layout

```
src/data/inspect.py   dataset schema report (run first)
src/data/graph.py     flow stream -> continuous-time dynamic graph
src/data/loader.py    real CSV/parquet loading, chronological splits
src/models/ct_tgnn.py CT-TGNN: graph ODE + multi-scale + TA-BN + point process
src/models/baselines/ EdgeBank, MLP, CNN-LSTM, discrete GNN, temporal attention
src/train.py          one model, one seed -> scores + metrics + manifest
src/report.py         runs -> LaTeX tables + figures (recomputed, never typed)
scripts/run_all.sh    full sweep
scripts/export_dyglib.py  export for TGN/TGAT/DyRep/JODIE/GraphMixer
```

## Reproducibility

Each run writes `manifest.json` recording the seed, full config, git
commit, hardware (GPU model, CPU, RAM), library versions, dataset
metadata, and the ODE solver actually used — the last matters because it
affects both accuracy and latency.

To verify any published number:

```bash
python -m src.report --runs runs --out /tmp/check
diff /tmp/check/table_main.tex paper/table_main.tex
```

## Baselines

`mlp_flow` (no topology) and `discrete_gnn` (snapshot) are ablation-style
controls isolating the contribution of graph structure and continuous
time respectively. For the full continuous-time suite — TGN, TGAT, DyRep,
JODIE, GraphMixer — use `scripts/export_dyglib.py` and run them in
[DyGLib](https://github.com/yule-BUAA/DyGLib), so that identical splits,
features, and tuning budgets hold by construction rather than by
assertion.

## Limitations

- Propagation metrics (source localisation, path reconstruction) require
  ground truth annotating *which node compromised which, in what order*.
  Standard NIDS benchmarks label flows, not propagation structure. Where
  that annotation is absent, only detection metrics are reported and no
  propagation claim is made.
- Latency figures depend on solver tolerance, hardware, and window size.
  All three are recorded per run; comparisons are only valid within a
  fixed configuration.
